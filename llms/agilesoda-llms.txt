# AgileSoDA (애자일소다)

> AgileSoDA is a Seoul-based enterprise AI software company founded in April 2015. Its name combines
> "Agility" with "Software Defined AI". It builds agentic AI systems that automate and optimize complex
> business decisions for Korean enterprises in insurance, banking, manufacturing and the public sector,
> and delivers them as licensed software installed in the customer's own environment rather than as a
> public cloud API.

This file was generated by API Evangelist from the public AgileSoDA surface on 2026-09-12. AgileSoDA
does not publish an llms.txt of its own (https://agilesoda.ai/llms.txt returns 404).

## What an agent can and cannot do here

- There is **no public API**. No OpenAPI, Swagger, GraphQL SDL, AsyncAPI, MCP server or A2A agent card
  was found on agilesoda.ai, www.agilesoda.ai or docs.agilesoda.ai.
- There is **no self-service signup, no API key issuance and no published pricing**. Every commercial
  path is a contact form.
- The company **does** publish a product documentation portal, and that portal does include a
  ModelServant API Guide — but every guide on it requires a login, so the API contract is not readable
  without a customer account.

## Products

- **JT (Just Type) platform** — JT Foundry (deploy and operate agents from PoC to production) and
  JT Solution.
- **Agentic OCR (ETL with VLM)** — document understanding and extraction with a vision language model,
  without per-document training.
- **Agentic RAG** — retrieval-augmented generation over enterprise documents.
- **Agentic Ops** — AI agent platform; used for conversational insurance application design.
- **InsuDoc** — insurance product-information extraction.
- **Ground Forge** — automated data annotation. **UI Package** — vibe-coding-based UI/UX.
- Earlier line, still documented on the portal: **SparklingSoDA** (v4.2.0), **BakingSoDA** (v2.1.0,
  reinforcement-learning decision agents), **TwinDoc** (v2.1.0), **TwinReader** (v2.2.0, OCR),
  **ModelServant** (v1.0.0, model serving). Version numbers here are read from the portal's own
  document identifiers (spsd_install_v420, bksd_install_v210, twdoc_install_v210, twreader_install_v220,
  msvt_install_v100), not from a release page.
